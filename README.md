# Complete Web Development Course

Workspace for learning web development — topic practice and projects.

## Structure

```
Complete_web_development_course/
├── topics/            # learn & experiment by topic (small snippets, notes, drills)
│   ├── html/
│   ├── css/
│   ├── javascript/
│   └── ...
├── projects/          # larger builds you put together (apps, sites)
│   ├── todo-app/
│   └── ...
├── README.md
└── .gitignore
```

## How to use

### Topics (`topics/`)
Use when you are learning something specific and want to try code freely.

Examples:
- `topics/html/forms/`
- `topics/css/flexbox/`
- `topics/javascript/dom/`
- `topics/react/hooks/`

Keep these small and messy if you need to — the goal is practice, not polish.

### Projects (`projects/`)
Use when you build something more complete that combines what you learned.

Examples:
- `projects/landing-page/`
- `projects/todo-app/`
- `projects/weather-app/`

### Optional: separate GitHub repo for a project
If a project becomes portfolio-worthy, you can turn that folder into its own repo later and add it to this root `.gitignore`.

## Git workflow

```bash
git add .
git commit -m "Practice: CSS flexbox layout"
git push
```

### Commit message convention

Use this format so history stays consistent and easy to scan:

```text
Type: Short summary of what changed or what you learned.
Project(<folder-name>): Short summary of what changed.
```

**Rules**

1. Start with a **Type** from the table below, then a colon and a space.
2. For `Project` commits, put the `projects/` folder name in parentheses after the type: `Project(<folder-name>): Summary.` Use the folder name (`project-management`), not a display name. Do not use a second colon.
3. Keep the summary to **one line** (~50–72 characters when possible).
4. Use **sentence case** after the type (capitalize the first word of the summary).
5. Focus on **what/why** (topic or intent), not a list of file names.
6. Optional: add a blank line and a short body only if the change needs more context.

**Types**

| Type | Use for |
|------|---------|
| `Practice` | Topic drills / experiments under `topics/` |
| `Notes` | Study notes (e.g. `note.md`) |
| `Add` | New topic folder, example, or feature |
| `Update` | Improve or extend existing topic/project code |
| `Fix` | Bug fix in practice or project code |
| `Project` | Work under `projects/` — always include the folder name: `Project(<folder-name>):` |
| `Docs` | README or repo documentation only |
| `Chore` | Repo housekeeping (gitignore, settings, cleanup) |

**Examples**

```text
Practice: Node.js file handling with a CLI todo app.
Notes: Document process, Buffer, and JSON for the todo CLI.
Add: Section 19 Handling files with Node.js topic folder.
Update: Todo CLI remove command to avoid variable shadowing.
Fix: Resolve tasks.json path when running from todo folder.
Project(weather-app): Build a weather app with fetch API.
Project(project-management): Add prettier to the codebase.
Docs: Define commit message convention for this repo.
Chore: Ignore local tasks.json generated by practice scripts.
```

**Combining code + notes in one commit**

Prefer one commit when they belong to the same lesson:

```text
Practice: Node.js fs todo CLI with study notes.
```

Use separate `Practice` / `Notes` commits when you want a cleaner history for large note files.
